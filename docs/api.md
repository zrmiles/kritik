# API «Критика»

Базовый адрес: `/api/`. Формат — JSON. Ошибки валидации возвращаются как `{"поле": ["сообщение"]}` с кодом `400`, ошибки доступа — `{"detail": "..."}` с кодом `401/403/404`.

## Аутентификация

JWT: короткоживущий **access**-токен (5 минут) передаётся в заголовке `Authorization: Bearer <token>` и хранится у клиента только в памяти. **Refresh**-токен (7 дней) сервер кладёт в cookie `kritik_refresh` с флагами `HttpOnly` и `SameSite=Lax` и ограничивает путём `/api/auth/`, поэтому JavaScript его не видит. При каждом обновлении refresh-токен меняется, а старый попадает в чёрный список.

Эндпоинты, которые работают с cookie (`register`, `login`, `refresh`, `logout`), защищены от CSRF: нужен заголовок `X-CSRFToken` со значением cookie `csrftoken`. Главная страница выдаёт эту cookie автоматически, а также её можно получить через `GET /api/auth/csrf/`.

| Метод | Путь | Доступ | Описание |
| --- | --- | --- | --- |
| GET | `/auth/csrf/` | все | Выдаёт cookie `csrftoken` |
| POST | `/auth/register/` | все | Регистрация: `username`, `display_name` (необязательно), `password`, `password_confirm`. Ответ `201`: `{user, access, access_expires_in}` + refresh-cookie |
| POST | `/auth/login/` | все | Вход: `username`, `password`. Неверные данные → `401 {"code": "invalid_credentials"}` |
| POST | `/auth/refresh/` | cookie | Новый access-токен по refresh-cookie. Нет/истекла cookie → `401` |
| POST | `/auth/logout/` | cookie | Отзывает refresh-токен, удаляет cookie. `204` |
| GET | `/auth/me/` | токен | Текущий пользователь `{id, username, display_name, public_name}` |

## Каталог игр

### `GET /games/` — список с фильтрами

Все параметры необязательны и применяются **одновременно**.

| Параметр | Пример | Значение |
| --- | --- | --- |
| `search` | `ведьмак` | Подстрока в названии, без учёта регистра (включая кириллицу) |
| `genre` | `action,indie` | Slug жанров через запятую — игра подходит, если есть **любой** из них |
| `platform` | `pc,nintendo-switch` | Slug платформ через запятую — **любая** из них |
| `year` | `2020` | Точный год выхода |
| `year_from`, `year_to` | `2018`, `2022` | Диапазон лет (включительно). `year_from > year_to` → `400` |
| `rating_min` | `8` | Минимальная средняя оценка, 1–10 |
| `reviewed` | `1` | Только игры, у которых есть рецензии |
| `ordering` | `rating` | `rating` (по умолчанию), `reviews`, `newest`, `oldest`, `title` |
| `page`, `page_size` | `2`, `12` | Пагинация; по умолчанию 24 на странице, максимум 60 |

Сортировка `rating`: средняя оценка по убыванию, игры без оценок — в конце, при равенстве выше игра с большим числом рецензий. Некорректные значения параметров возвращают `400` с указанием поля.

Ответ:

```json
{
  "count": 5,
  "next": null,
  "previous": null,
  "results": [
    {
      "id": 9,
      "slug": "baldurs-gate-3",
      "title": "Baldur's Gate 3",
      "description": "…",
      "release_date": "2023-08-03",
      "cover_url": "",
      "poster_theme": "oxblood",
      "genres": [{"slug": "role-playing-games-rpg", "name": "Ролевая"}],
      "platforms": [{"slug": "pc", "name": "PC"}],
      "data_source": "manual",
      "source_url": "",
      "average_rating": "9.00",
      "review_count": 4,
      "is_saved": false
    }
  ]
}
```

`average_rating` — строка с двумя знаками после запятой или `null`, если оценок нет. `is_saved` учитывает текущего пользователя (для гостя всегда `false`).

### Остальные запросы каталога

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/games/{id}/` | Игра + `score_distribution`: массив из 10 чисел — сколько раз поставили 1, 2, …, 10 |
| GET | `/games/filters/` | Значения для фильтров: `genres` и `platforms` (`slug`, `name`, `count`) — только те, что встречаются в каталоге; `years`; `orderings` |
| GET | `/games/stats/` | Сводка: `games`, `reviews`, `critics` (пользователи с рецензиями), `last_review_at` |

Создание, изменение и удаление игр — через админку Django (`/admin/`) и импорт из RAWG; обычные пользователи игры менять не могут.

## Рецензии

Шкала оценок 1–10, текст 10–500 символов, **одна рецензия на игру от пользователя** (ограничение в БД). Средняя оценка и число рецензий считаются агрегатом в запросе, поэтому сразу отражают любое изменение.

| Метод | Путь | Доступ | Описание |
| --- | --- | --- | --- |
| GET | `/games/{id}/reviews/` | все | Рецензии игры, новые сверху. Поле `is_owner` помечает рецензию текущего пользователя |
| POST | `/reviews/` | токен | Создать: `game_id`, `score`, `text`. Повтор → `400` |
| GET | `/reviews/{id}/` | автор | Своя рецензия |
| PATCH | `/reviews/{id}/` | автор | Изменить `score` и/или `text`. Перенести на другую игру нельзя |
| DELETE | `/reviews/{id}/` | автор | Удалить, `204` |
| GET | `/me/reviews/` | токен | Все мои рецензии с краткими данными игры |

Чужую рецензию изменить или удалить нельзя: для не-автора она не существует (`404`).

## Личный список

| Метод | Путь | Описание |
| --- | --- | --- |
| GET | `/me/saved-games/` | Мой список, новые сверху: `[{game: {...}, created_at}]` |
| POST | `/me/saved-games/` | Добавить: `{"game_id": 5}`. Повтор → `400` |
| DELETE | `/me/saved-games/{game_id}/` | Убрать игру, `204` |

Все запросы требуют токен; каждый видит и меняет только свой список.

## Импорт из RAWG

Не HTTP-эндпоинт, а команда администратора:

```bash
cd src && python manage.py import_rawg --pages 3 --ordering -rating --details
```

| Параметр | По умолчанию | Описание |
| --- | --- | --- |
| `--pages` | 1 | Сколько страниц загрузить |
| `--page-size` | 40 | Игр на странице (1–40) |
| `--search` | — | Загрузить только найденные по запросу |
| `--ordering` | `-added` | Порядок RAWG: `-rating`, `-released`, `-metacritic` … |
| `--details` | выкл. | Дополнительно загрузить описание каждой игры (один запрос на игру) |

Игра ищется по паре (`data_source`, `external_id`), поэтому повторный импорт обновляет записи, а не создаёт дубликаты. Каждый запуск записывается в журнал `ImportRun` (админка → «Import runs»): статус, число новых и обновлённых игр, текст ошибки. Если RAWG недоступен, импорт прерывается с понятной ошибкой, а каталог продолжает работать на уже сохранённых данных.
