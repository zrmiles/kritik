# Процесс и шаблоны

Шаблоны для артефактов, которые требует задание. Заполняйте их реальными данными по ходу работы — задним числом протоколы и опросы не пишутся.

## Git

- `main` — всегда рабочая версия; напрямую в неё не пушим.
- Задача → ветка `feature/<коротко>`, `fix/<коротко>` или `docs/<коротко>`.
- Коммиты — в повелительном наклонении и по одному смыслу: `Добавить фильтр по диапазону лет`, `Исправить пересчёт рейтинга при удалении`.
- Pull request: описание, ссылка на задачу, как проверить. Сливаем после зелёного CI и ревью техлида.
- Никогда не коммитим `.env`, `db.sqlite3`, `.venv/`, ключи API.

## Недельный цикл (из задания)

| День | Что происходит | Кто ведёт |
| --- | --- | --- |
| Понедельник | Планирование спринта, оценка задач | PM, техлид |
| Вторник–четверг | Разработка, короткие стендапы | все |
| Пятница | Отчёт, код-ревью, деплой, подготовка демо | PM, техлид, DevOps |
| Суббота | Ретроспектива | DevOps/QA |

## Протокол встречи

```markdown
### <Стендап | Планирование | Ретро> — ДД.ММ.ГГГГ
Присутствовали: …
Сделано со времени прошлой встречи: …
План: …
Блокеры: …
Решения: …
```

## Отчёт на практическом занятии (раз в 2 недели)

```markdown
## Отчёт за ДД.ММ–ДД.ММ
1. Ключевые достижения:
2. Запланировано, но не сделано (и почему):
3. План на следующую неделю:
4. Проблемы и блокировки:
5. Вклад участников:
   - ФИО — роль: задачи, ссылки на PR
6. Метрики и артефакты: коммиты, закрытые истории, число тестов, ссылка на демо
```

## Мини-опрос пользователей (для PM)

Вопросы (3–5, по заданию):

1. Как вы обычно выбираете, во что поиграть дальше? (обзоры изданий / оценки в магазине / друзья / видео / другое)
2. Доверяете ли вы оценкам изданий и магазинов? Почему?
3. По каким признакам вы фильтруете игры? (жанр, платформа, год, цена, длительность, оценка)
4. Ведёте ли вы список игр «на потом»? Где?
5. Стали бы вы писать короткую рецензию после прохождения? Что вас мотивирует или останавливает?

Результаты: число опрошенных, сводная таблица ответов, 3–5 выводов для бэклога.

## Структура презентации (12–14 слайдов, 15 минут)

1. Проблема · 2. Решение · 3. Технологии и архитектура (с авторами модулей) · 4. Рынок и конкуренты (Metacritic, OpenCritic, Backloggd, Steam-отзывы) · 5. Бизнес-модель · 6. Демо (с авторами функций) · 7. Команда и роли · 8. Индивидуальные достижения · 9. Результаты и метрики · 10. План развития · 11. Заключение.

Сценарий живого демо: регистрация → фильтры в каталоге → страница игры → рецензия и пересчёт оценки → личный список → выход и повторный вход → журнал импорта RAWG в админке.
