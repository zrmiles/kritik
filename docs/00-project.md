> Лабораторная работа № 1 «Запуск проекта». Документ описывает исходное состояние проекта на момент начала семестра и план работ. Требования (UR/FR/NFR) вводятся в лабораторной работе 2.

## 1. Паспорт

| Поле | Значение |
| --- | --- |
| Название | **Критик**: агрегатор пользовательских отзывов на видеоигры |
| Происхождение | Собственный проект. Начат 26.09.2026 в рамках дисциплины «Проектный практикум», с ЛР 1 развивается как проект курса. Отправная точка: коммит `a63d112` ветки `main` |

### Назначение и решаемая проблема

Игроку, который выбирает следующую игру, трудно понять, стоит ли она внимания. Оценки в магазинах и у изданий смешаны с маркетингом, а мнения на форумах разрознены и не сводятся к короткому ответу. «Критик» собирает каталог игр из открытой базы RAWG и показывает по каждой игре только оценки и короткие рецензии пользователей сервиса: среднюю оценку, распределение оценок от 1 до 10 и тексты. Каталог можно искать и фильтровать, а интересные игры сохранять в личный список «сыграть позже».

### Целевые пользователи и роли

| Роль | Кто это | Что может |
| --- | --- | --- |
| **Гость** | Посетитель без аккаунта | Искать и фильтровать каталог, открывать страницу игры и читать рецензии, зарегистрироваться |
| **Пользователь** | Зарегистрированный игрок | Всё, что гость, а также писать, изменять и удалять свою рецензию с оценкой, вести личный список, смотреть свои рецензии |
| **Администратор** | Ответственный за каталог | Импортировать игры из RAWG, создавать, изменять и удалять игры, жанры и платформы, модерировать рецензии, смотреть журнал импорта |
| **RAWG API** (внешняя система) | Открытая база видеоигр `api.rawg.io` | Отдаёт сведения об играх: название, дату выхода, обложку, жанры, платформы и описание |

### Сущности предметной области

| Сущность | Модель | Смысл |
| --- | --- | --- |
| Игра | `games.Game` | Карточка игры: название, дата выхода, обложка, описание, источник данных (вручную или RAWG) |
| Жанр | `games.Genre` | Справочник жанров, связь M:N с игрой |
| Платформа | `games.Platform` | Справочник платформ, связь M:N с игрой |
| Рецензия | `reviews.Review` | Оценка 1–10 и текст 10–500 символов. На каждую игру у пользователя не больше одной рецензии |
| Запись личного списка | `saved_games.SavedGame` | Игра, отложенная пользователем «на потом» |

Служебные модели: `accounts.User` (пользователь) и `games.ImportRun` (журнал запусков импорта).

### Три основные функции

1. **Поиск по каталогу.** Поиск по названию, в том числе на кириллице, одновременно с фильтрами по жанрам, платформам, годам выпуска, минимальной оценке и наличию рецензий. Пять сортировок.
2. **Рецензии и оценка сообщества.** Пользователь создаёт, изменяет и удаляет свою рецензию, средняя оценка игры сразу пересчитывается.
3. **Импорт каталога из RAWG.** Повторный импорт не создаёт дубликатов, ошибки провайдера пишутся в журнал, а сервис продолжает работать на сохранённых данных.

### Внешние зависимости и сервисы

| Зависимость | Как используется | Обязательна? |
| --- | --- | --- |
| PostgreSQL 16 | Основная БД в Docker и CI | Нет: без `POSTGRES_DB` используется SQLite |
| RAWG API (`api.rawg.io`) | Импорт сведений об играх командой `import_rawg`, ключ `RAWG_API_KEY` | Нет: без ключа работает демо-каталог |

Очередей сообщений, кэша и других внешних сервисов нет.

### Хранение данных

Реляционная БД через Django ORM. По умолчанию это SQLite в файле `src/db.sqlite3`, при заданной переменной `POSTGRES_DB` используется PostgreSQL. Схема создаётся миграциями (`src/*/migrations/`). Средняя оценка и число рецензий не хранятся в отдельных полях, а вычисляются агрегатами при запросе (`GameQuerySet.with_review_stats`). Refresh-токены хранятся в таблицах `token_blacklist`, чтобы их можно было отозвать при выходе. Файлы пользователей не загружаются.

### Конфигурация

Настройки задаются переменными окружения в `src/config/settings.py`. Локально они читаются из файла `.env` в корне репозитория (образец: `.env.example`), в Docker передаются через `docker-compose.yml`.

| Переменная | По умолчанию | Назначение |
| --- | --- | --- |
| `DJANGO_SECRET_KEY` | небезопасный ключ разработки | Подпись сессий и JWT |
| `DJANGO_DEBUG` | `true` | Режим отладки |
| `DJANGO_ALLOWED_HOSTS`, `DJANGO_CSRF_TRUSTED_ORIGINS` | `127.0.0.1,localhost`, пусто | Допустимые адреса |
| `JWT_COOKIE_SECURE` | `false` | Отправлять refresh-cookie только по HTTPS |
| `POSTGRES_DB`, `POSTGRES_USER`, `POSTGRES_PASSWORD`, `POSTGRES_HOST`, `POSTGRES_PORT` | пусто, то есть SQLite | Подключение к PostgreSQL |
| `RAWG_API_KEY`, `RAWG_BASE_URL`, `RAWG_TIMEOUT` | пусто, `https://api.rawg.io/api`, `15` | Доступ к RAWG |
| `SEED_DEMO`, `IMPORT_RAWG_PAGES` (только Docker) | `1`, `0` | Загружать ли демо-каталог и сколько страниц импортировать при старте |
| `WEB_PORT` (только Docker) | `8000` | Порт приложения на хосте |

## 4. Карта функций

Все функции уже реализованы. Ручная проверка выполняется на запущенном сервисе (<http://localhost:8000>) с демо-каталогом.

| № | Функция | Роль | Реализация | Как проверить вручную |

Неверный пароль выдаёт сообщение об ошибке |
| Ф2 | Поиск, фильтры и сортировки каталога | Все | `src/games/views.py` (`GameListView`, `GameQuerySetMixin`), `GameFiltersView` | Ввести «мор»: находится «Мор (Pathologic 2)». Выбрать два жанра, платформу, «с 2018», «8+» и проверить, что число «Найдено» совпадает с карточками. Скопировать адрес в новую вкладку: фильтры сохранились |
| Ф3 | Страница игры: сведения, оценка, гистограмма, рецензии, похожие игры | Все | `src/games/views.py` (`GameDetailView`), `src/reviews/views.py` (`GameReviewListView`) | Открыть игру с рецензиями: видны средняя оценка, распределение 1–10 и источник данных. | Ф4 | CRUD своей рецензии с пересчётом средней | Пользователь | `src/reviews/views.py` (`ReviewCreateView`, `ReviewDetailView`), `serializers.py` | Написать рецензию с оценкой 9, изменить оценку на 5, удалить. | Ф5 | Личный список «сыграть позже» | Пользователь | `src/saved_games/views.py` | Нажать «В список» на карточке, открыть «Мой список», убрать игру. Гостю предлагается войти |
| Ф6 | Страница «Мои рецензии» | Пользователь | `src/reviews/views.py` (`MyReviewListView`) | После публикации рецензии она появляется в разделе «Мои рецензии» |
| Ф7 | Сводка каталога на главной (игры, рецензии, критики) | Все | `src/games/views.py` (`CatalogStatsView`) | После публикации рецензии счётчик на главной увеличивается |

| Ф9 | Администрирование: CRUD игр, жанров, платформ, модерация рецензий | Администратор | `src/games/admin.py`, `src/reviews/admin.py`, `src/accounts/admin.py` | `createsuperuser`, войти в `/admin/`, создать игру вручную и найти её в каталоге, удалить чужую рецензию |

| Нехватка времени из-за параллельных дисциплин | Организационный | Высокая | Средние: срыв сроков отдельных ЛР | Основная функциональность уже готова, поэтому в семестре остаются документация, тесты и 1–2 небольшие функции. Работы планируются с запасом около 20 %, объём новых функций можно сократить |
| Работа в одиночку: нет независимого ревьюера и тестировщика | Организационный | Высокая | Средние: ошибки, которые замечает только второй человек | CI как обязательная проверка перед слиянием, чек-листы в `docs/testing.md`, smoke-тест, самопроверка PR по шаблону. Замечания преподавателя оформляются как issues |
| Незнакомые технологии (Mermaid, оформление ADR, coverage, Playwright для e2e) | Технический | Средняя | Низкие | Изучать по ходу работ, начать с минимального варианта. Сложные e2e-тесты необязательны |
| Изменения в Django 5.2 или зависимостях ломают сборку | Технический | Низкая | Средние | Точные версии в `requirements.txt`, CI на каждый PR. Обновления выполняются отдельными PR |
| Платные сервисы для развёртывания | Внешний | Средняя | Средние: нет публичного стенда | Основной сценарий выпуска — Docker-образ и docker compose на любой машине. Публичный стенд разворачивается на бесплатном тарифе, если он доступен |
| Потеря данных или рабочего окружения | Технический | Низкая | Высокие | Весь код и документация на GitHub, данные воспроизводятся миграциями и `seed_demo` |

**Вывод.** Проект выполним за семестр: ядро уже реализовано и проверено автотестами, а внешние риски не блокируют работу благодаря демо-каталогу. Основной риск — нехватка времени, его снижает небольшой объём новой разработки.
